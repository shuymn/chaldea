## 1. Goal and Dependencies

**Goal.** After a daemon crash, the recorded leader of every unconfirmed `daemon_restart` launch, including one an earlier start reconciled, and the recorded child of every unconfirmed `spawn_failed` launch whose `failed_start` names a pid and a start time are signalled by verified identity in each daemon start that reaches its probe, without any command; what each check observed dead, observed alive, or did not observe is recorded as `launch_evidence`, as is what an owned close or a failed start could not prove; the owner reads it with `chaldea stop <thread> --assume-dead` and confirms one launch with `--launch <id>`, which is then the only way such a launch unlocks; and PR 21's finder receives what it needs for A29.

**Depends on** PR 10a1 (sup §2.12 "What 10a1 records for it", "Where 10a2 plugs in") and PR 10b, both merged.

## 2. Design

### 2.1 Rules

1. **Nothing after a crash confirms death but the owner.** A probe signals only verified identities and records what it observed; it never writes `launch_death_confirmed` and never changes state (owner decision).
2. **Evidence separates three classes.** Each recorded identity a check covered is observed dead, observed alive, or not observed, and each record lists what the check did not cover (§2.4).
3. **Probe work is admitted and counted while it can signal.** A probe's blocking task holds a tracker token from an admission atomic with shutdown until it can no longer signal, and holds its concurrency slot the same way (§2.3).
4. **One prober per start, candidates from the store.** The set is read after `attach` from the projection, so a launch an earlier start reconciled is probed again by every later start until the owner confirms it (RD1).

**Identity trust.** A recorded identity is trusted as the launch's because only the daemon writes `launch_started` and `launch_exited.failed_start`, into a private store (daemon-lifecycle §2.4). A row edited to carry an exact `(pid, start_time)` of an unrelated live process would get that process signalled, as an `extra` would (pty-windows §2.5 "Extras are trusted input").

### 2.2 `orphan::kill_recorded`

The daemon crate has no OS dependency (sup §2.5; `crates/daemon/Cargo.toml`), so the unowned kill lives in pty-runtime, beside the owned engine it must not reuse (pty-unix §4 row "Daemon restart"; RD10):

```rust
// crates/pty-runtime/src/orphan.rs (new)
pub enum Fate { Gone, Replaced, Alive, Unreadable, NotRead, WaitFailed, Invalid }
pub struct OrphanReport { pub fates: Vec<(ProcessIdentity, Fate)> }   // input order, identical identities collapsed
pub fn kill_recorded(identities: &[ProcessIdentity], deadline: Instant) -> OrphanReport;
```

- **Validation.** An identity is `Invalid`, never read or signalled, when its pid is 0, the daemon's own, 1 (macOS), greater than `i32::MAX` (macOS: it does not fit `pid_t`, and `bsd_info` would answer `ESRCH` for it, `unix/sys.rs:221-224`), or 4 (Windows), or its `start_time` does not parse as `u64` (empty included). This extends the engine's acceptance rule (`unix/kill.rs:518-524` `accept`; pty-windows §2.5 "Extras").
- **Deadline.** The clock is read before every native call, including each of a read's two calls on macOS, and no call starts at or after `deadline`; every sleep and wait is clipped to `deadline − now` (pty-unix §2.5 "Deadline discipline", pty-windows §2.5 "Clock rules"). The tolerance is one native call in flight at the deadline.
- **macOS**, over `OrphanOs` (new, `pub(crate)`): `bsd_info`, `short_zombie`, `kill`, `now`, `sleep`, each one native call, and nothing else, so the type has no list, `getsid`, or group call (RD10). A read is `bsd_info`, then, only when that was refused with anything but `ESRCH`, `short_zombie` after its own clock check, both classified by `unix/table.rs`'s `classify` (`:30-52`); a read cut between its two calls counts as refused. With `t0` the entry and `B = deadline − t0`: a round of HUP, reads every 25 ms until `t0 + min(500 ms, B/4)`, a round of TERM, reads until `t0 + min(2 s, B/2)`, a round of KILL, reads every 25 ms until every identity is resolved or the deadline; with `B ≤ 100 ms` only the KILL round. A round reads each unresolved identity and signals it only when that read showed `Live` with the recorded start, with only the clock check between the read and `kill(2)` (pty-unix §2.5 `signal_verified`, the positive-pid checked call). A read showing `Gone` or a zombie resolves `Gone`; `Live` with another start, `Replaced`. An identity unresolved at the end is classified by its last read alone: none → `NotRead`; `Live` with the recorded start → `Alive`; refused → `Unreadable`.
- **Windows**, over `ProcessOs` (new, `pub(crate)`, split out of `JobOs`, `windows/kill.rs:46-62`): `now`, `sleep`, `open_process`, `creation_time`, `signalled`, `terminate`, and no job method; `JobOs: ProcessOs`, and `open_verified` takes a `ProcessOs`. The real orphan implementation holds no job handle (the engine's `RealJobOs` holds one, `windows/child.rs:123-127`). One `open_verified` per valid identity (`Held` kept; `Gone` → `Gone`; `Stale` → `Replaced`; `Unverifiable` → `Unreadable`; `Cut` → `NotRead`, and no further open); then `terminate` on every held handle, before any wait; then rounds of `signalled` on each unsignalled held handle, each wait clipped, until all are signalled or the deadline. A held handle's fate is its last wait's: `Ok(true)` → `Gone`; `Ok(false)` → `Alive`; `Err` → `WaitFailed`, and that handle gets no further wait, so a failing handle cannot spin a worker until the deadline; no wait made before the deadline → `NotRead`.

### 2.3 Restart prober

`SupervisorComponents::attach` spawns `prober::run(sup)` after its 10a1 steps; startup does not wait for it, and the HTTP server starts serving at step 13 meanwhile (`lifecycle/startup.rs:676`, `:736`). The prober, in order:

1. `Pause::ProberStart`. If `Tracker::accepting()` is false (shutdown began), it returns.
2. *Candidates.* One read transaction on a blocking task, `ReadTx::open_launches()` (`readers.rs:815-822`: `exit_reason IS NULL OR death_confirmed = 0`), awaited with `settle_before` and `in_time()` until its start + `PROBE_READ` (10 s), as the stop's re-read is bounded (sup §2.3 Stop step 2). It keeps, in `(thread_id, reserved_seq)` order, the rows with death unconfirmed and a recorded identity: `exit_reason = daemon_restart` with `pid` recorded, whose identity is the row's `{ pid, start_time, group: pgid_or_job }`, an absent text as empty (then `Invalid`); and `exit_reason = spawn_failed` whose `launch_exited`, read in the same transaction by its key, carries a `failed_start` with a non-empty `start_time`, whose identity is that child's `{ pid, start_time, group: pgid_or_job }`. A `daemon_restart` row's process is from an earlier run, since this run's own launches never get that reason; a `spawn_failed` launch's kill ended before its exit was recorded, so the daemon holds no session or job of it. The prober therefore cannot reach a launch this daemon owns. It validates nothing more: an identity `kill_recorded` refuses (§2.2: pid 0, pid 1 on macOS or 4 on Windows, the daemon's own pid, a pid above `i32::MAX` on macOS, a start it cannot parse) is neither read nor signalled and is recorded `invalid`, so the owner sees it. A read not returned in time ends the prober with a log line; the next start reads again.
3. *Per candidate*:
   1. A slot: `Supervisor.probe_slots` (a `tokio::sync::Semaphore` of `PROBE_SLOTS` = 4) `acquire_owned`, awaited with `settle_before` and `in_time()` until now + `SLOT_WAIT` (30 s); a `Late` permit is dropped at once. No slot in time ends the prober with the remaining launches logged; each holder's work ends at its own deadline unless the blocking pool or the OS stalls, so a 30 s wait means such a stall.
   2. *Admission.* A `TrackToken` from `Tracker::admit` (sup §2.9), which takes the tracker's mutex for its check, so a probe is admitted before admission closes or never, wrapped in a `ProbeAdmission` (new), whose drop calls `TrackToken::release`. `None` → the prober drops the permit and returns.
   3. The identity from step 2. An attempt id, a UUID v4 the prober mints now. `deadline = now + PROBE_BUDGET` (5 s).
   4. `spawn_blocking` of a closure that owns the permit and the `ProbeAdmission`. Started, it passes `Pause::ProbeQueued`, then sets its start mark inside `Tracker::while_accepting` (admission's mutex, `Pause::ProbeStarting` before the mark), so it starts before admission closes or never: admission closed (shutdown began while it was queued) → no OS call and no evidence. Else, the mutex released, it calls `SupervisorConfig.kill_recorded` (`orphan::kill_recorded` outside tests) with `[identity]` and `real(deadline)`. The closure's end drops both, on a return, on an unwind out of `kill_recorded`, and when the blocking pool drops the closure unrun: in each the worker can no longer signal. The slot is therefore returned when the blocking work ends, not when the prober stops waiting for it (sol r3 #2b); the participant counts the worker exactly while it can signal (sol r1 H1); and a probe that panicked does not keep later shutdowns from `Clean` (sol r2 M1). This is the probe's own release rule: sup §2.9's rule (dropping is never a release, `tracker.rs:163-175`) counts processes and handles, and a probe owns neither.
   5. A task of its own awaits the join with `settle_before` until `deadline + PROBE_JOIN_GRACE` (1 s). `InTime(Ok(report))` and `Late(Ok(report))` give the fates: a late report is still an observation. `Elapsed`, or a join error (a panic), gives every identity `NotRead` and adds `result_not_received`. A worker that never reached its OS call (dropped unrun, or finding admission closed) records nothing, whatever the join outcome: it marks itself started right before `kill_recorded`, and the record task reads that mark apart from the join, so a probe cancelled while queued writes no evidence even after its join cutoff passed. Otherwise that task records the evidence (§2.4) through `supervisor::record` with `nudge: false`; the job appends one event and changes no state.
4. The prober returns once every candidate's task is spawned.

**Shutdown** (sol r1 H1). The token makes probe work part of the participant's count: admission is closed by `Tracker::close_admission` under the same mutex as `admit` (sup §2.9 step 1), so a probe either was admitted before the close or never starts; a queued task admitted before it finds admission closed and makes no OS call; a task queued or running at the participant's `end` still holds its token and keeps the count nonzero, so the participant answers `LeftRunning`, the daemon exits with the instance lock held, and no next daemon probes the same launch while this one can still signal (sup §2.9 "The lock rule"). The process exit then abandons such a worker with the blocking pool (sup L-8): it may have sent HUP or TERM without KILL, and the next start probes the launch again (L-6). The prober itself holds no token while it waits for a slot or a read.

**Evidence write** (sol r1 M7). `supervisor::record` retries the same job, the same payload under the same key, on its retryable outcomes, within its budget (sup §2.10 "Store jobs"); once the writer admits an attempt, the task awaits that ticket to the writer's answer, as every admitted attempt is awaited (sup Commitment #2), holding neither slot nor token. `Unrecorded` and `ShuttingDown` are logged and the evidence is dropped. A `CommitUnknown`, `WriterGone`, or `Failed` answer is reported to the lifecycle sink by `write_with` (`http/ctx.rs:286-300`), which starts the daemon's shutdown as it does for every supervisor job: a store that cannot say whether it committed is not trusted for any later write either; the next start probes the launch again. No record or join outcome starts a second OS probe of a launch in the same start.

**Assertion during a probe** (sol r1 M4). The prober does not re-read a candidate after its candidate read. An assertion committed before the probe's dispatch, or while its worker runs, does not stop it (PR10a2-CL-8 `assertion_race`): the probe signals only the launch's verified recorded identity (a `daemon_restart` leader or a failed start's child), and its evidence is appended after the confirmation and changes nothing. The preview prints evidence recorded after a confirmation under that confirmation (§2.5).

**What the prober does not do.** It probes no `unknown_after_crash` launch (no identity), no `stopped` or `exit` launch, and no `spawn_failed` launch without a `failed_start` naming a start time: their sessions were closed by the owned kill, whose report is recorded as evidence (§2.4). A failed start's child is the exception because its identity is recorded outside any session the kill closed, and P-18 fails for it if it is alive (RD9). `stop` probes nothing (RD2).

### 2.4 Evidence

A new thread-stream event kind, `launch_evidence`, records one check. It changes no state: the projection's arm is a no-op (`crates/daemon/src/store/project.rs`, beside `MailboxMessage` and the others at `:457-461`), it has no `Content` field (`store/content.rs:175-178`), and an older client decodes it as a generic event (`event.rs:215-231`). It is additive under mvp §2.1 "`schema_version`".

```rust
// crates/core/src/payload.rs (new)
pub struct LaunchEvidence {
    pub launch_id: LaunchId,
    pub source: EvidenceSource,                // "spawn_failed" | "close" | "probe"
    pub identities: Vec<IdentityObservation>,  // each recorded identity the check covered, one per pid
    pub unchecked: Vec<Unchecked>,             // what the check did not cover; never empty (the sources table)
    pub probe_run: Option<String>,             // the probing daemon run's instance UUID; null for the other sources
}
pub struct IdentityObservation { pub pid: u32, pub start_time: Option<String>, pub observed: Observed }
pub enum Observed { Gone, Replaced, Alive, Unresolved, Unreadable, NotRead, WaitFailed, Invalid }
pub enum Unchecked { UnrecordedSessionMembers, UnrecordedJobAndOutsideJob, TreeUnproven, NoIdentity, CleanupUnreleased, ResultNotReceived }
pub const OWNER_ASSERTED: &str = "owner_asserted";
```

Every field is always present (`payload.rs`'s rule); an identity's empty `start_time` (`ProcessIdentity`'s form for an unknown start, `windows/mod.rs:936-940`, `unix/kill.rs:133-136`) is written as `null`. **Envelope:** `launch_id` is `L`, `command_id` is `null`, and `source.kind` is the exit job's own (`process`, or `daemon` at restart, `exit.rs:106-110`) for `spawn_failed` and `close`, and `daemon` for `probe`.

| `observed` (wire) | Class | Meaning |
|---|---|---|
| `gone` | dead | a read showed the pid gone or a zombie, its handle was signalled, or a proving kill report covered it |
| `replaced` | dead | the pid holds a process with another start, so the recorded one ended |
| `alive` | alive | the last read before the deadline showed the recorded start, or the last wait on its handle returned unsignalled |
| `unresolved` | not observed | a kill report listed it as a survivor: not shown dead, without saying whether its last read was live or refused |
| `unreadable` | not observed | the last read was refused |
| `wait_failed` | not observed | the last wait on its handle failed |
| `not_read` | not observed | no read or wait before the deadline, or the check's result did not reach the daemon in time |
| `invalid` | not observed | never read or signalled (§2.2 "Validation") |

| `unchecked` (wire) | Meaning |
|---|---|
| `unrecorded_session_members` | macOS probe: members of the old session without a recorded identity (L-1; RD9) |
| `unrecorded_job_and_outside_job` | Windows probe: processes without a recorded identity, members of the old job, terminated by `KILL_ON_JOB_CLOSE` when the old daemon exited, and processes outside it, none observed (L-2); a recorded child listed in the same evidence is not in this scope |
| `tree_unproven` | the owned kill did not prove the tree dead: processes it did not list may exist |
| `no_identity` | no identity was recorded for the launch's leader; a failed start's survivors listed in the same evidence are not in this scope |
| `cleanup_unreleased` | the tree was proven dead, but the backend's cleanup of a failed start did not complete |
| `result_not_received` | the check's result did not reach the daemon by its cutoff |

**Sources** (each appended in the job named, right after `launch_exited` when in the exit job, so every evidence event of a launch has a higher seq than its `launch_exited`):

| Source | Written when, in which job | `identities` | `unchecked` | Idempotency key |
|---|---|---|---|---|
| `spawn_failed` | the exit job of a `StartedThenFailed` whose cleanup is `Cleanup::Unresolved` (sup §2.3 step 6, where 10a1 only logs, `ops.rs:206`), and of a `Session::spawn` that panicked (`ops.rs:228-241`) | with a returned identity: `gone` when `Unresolved.kill` is a proving report (`ops.rs:660-662` `proving`); else that report's survivors together with the identity, one per pid (the backends already list the leader, `unix/kill.rs:530-540`, `windows/kill.rs:325-338`), each `unresolved`; without one, a non-proving report's survivors, each `unresolved`; none after a panic | `no_identity` when none was returned (a panic included); `cleanup_unreleased` with a proving kill; `tree_unproven` without one; `result_not_received` after a panic | `launch:<L>:evidence:spawn_failed` |
| `close` | the exit job of a stop, a natural exit, the participant, or a late creation whose death is unconfirmed (`ops.rs:731-741`, `:1092`) | the kept report's survivors (below), each `unresolved` (possibly none) | `tree_unproven`; and `result_not_received` when the close's receipt is `NotReceived` | `launch:<L>:evidence:close` |
| `probe` | the prober's record job (§2.3) | the probed identity (a `daemon_restart` leader or a failed start's recorded child) with its `Fate` (`not_read` on a result not received) | `unrecorded_session_members` (macOS) or `unrecorded_job_and_outside_job` (Windows); `result_not_received` when so | `launch:<L>:evidence:probe:<attempt>` |

**Which report a `close` keeps** (sol r1 M3, r2 M5; Neon r1 LOW). `ops::Proof` (`ops.rs:749-776`) keeps only a proving report today. It gains `close: CloseReceipt` (new), `InTime(KillReport)` (the close's `CloseOutcome.kill`, its join received before the cutoff) or `NotReceived(Option<KillReport>)`; `result_not_received` is written exactly for `NotReceived`. The `Option` is the last non-proving `kill_by` report the kill task published (the reports 10a1 logs at `ops.rs:731-733`): the task writes it with its publication instant, read on the supervisor clock while it holds the slot, into a slot under a `std::sync::Mutex` held only for the copy and that read (`Pause::KillReportPublish` precedes the write), and the op, once both waits are classified, reads the slot with one `try_lock` and keeps the report only if it was published before the cutoff (a held lock or a later report → `None`). The participant's and a late creation's close (`ops.rs:1068-1100`) build no `Proof`: their evidence comes from the `CloseOutcome` received by `close_end`, and a close not received by then records no exit (sup §2.9 class 3), so no evidence.

The first two sources are written at most once per launch, as `launch:<L>:exited` is: `exit_in` writes nothing for a launch that already exited (`exit.rs:102-104`), and `ExitPlan.evidence` rides that job. A probe's attempt id is a server-minted UUID, never a client value, so no client `command_id` shares its namespace; a key reused with other content is `KeyConflict` (`write_tx.rs:487-515`), which the fixed payload of a retried job never produces.

### 2.5 Owner Assertion and Preview

**Wire.** `StopArgs` gains `assume_dead: bool` with `#[serde(default, skip_serializing_if = "<false>")]`, so a plain stop's canonical arguments (`supervisor/commands.rs:38-45` `parse`, `CanonicalJson::of`) and request identity stay byte-equal to 10a1's, and a stored 10a1 receipt replays (sol r1 M1); `true` serializes and gives another request identity. `deny_unknown_fields` stays, so a new CLI's plain stop, which omits the field, reaches an old daemon unchanged. `StopOutcome` gains `asserted`, returned only to a request with `assume_dead: true`. `StopResult` keeps its fields: `{ launch_id, outcome, death_confirmed, confirmed_within_deadline, exit_code, signal }`.

**`prepare`**: `assume_dead` without `expected_launch_id` → 400 `bad_args`.

**Intent**, with `assume_dead`, in this order: the target scope (sup §2.2, `supervisor/commands.rs:73` `target`; 404 for a thread the token cannot read); a token whose `kind` is not `TokenKind::Owner` → 403 `forbidden` (classified at `http/commands.rs:139`); the current launch `L` ≠ `expected_launch_id` → `launch_changed`; `L` without `exit_reason` → `launch_live`; `L` exited with death confirmed → the confirmed-launch result below, nothing written; else, in the intent's own job, `launch_death_confirmed { launch_id: L, method: "owner_asserted" }` under the key `launch:<L>:death_confirmed` with `StateInput::DeathConfirmed` (which clears `resume_blocked`, `state.rs:327-331`), and `Completed(StopResult { launch_id: L, outcome: asserted, death_confirmed: true, confirmed_within_deadline: false, exit_code: null, signal: null })`. Without `assume_dead` the intent is 10a1's, `death_unconfirmed` included.

Every reason applies: `daemon_restart`, `unknown_after_crash`, an unconfirmed `stopped` or `exit`, `spawn_failed`. The assertion requires no evidence; what the owner reads first is the preview's job, not the daemon's (L-9).

**A confirmed launch's result** (sol r1 M5, r2 M4; orchestrator decision). Wherever 10a1 answers `already_exited` (the stop intent, `supervisor/commands.rs:255-259`, and the op's re-read, `ops.rs:826-833`), a row whose `death_method` (`rows.rs:61`) is `owner_asserted` is answered, nothing written: to a plain `stop`, `already_exited` with `confirmed_within_deadline: false`, so a 10a1 CLI, whose `StopOutcome` has no `asserted` (`command.rs:178-186`), still decodes it; to an `assume_dead` request, `asserted` with `confirmed_within_deadline: false`. So `confirmed_within_deadline: true` never stands on an assertion. The CLI prints the `StopResult` JSON on stdout in every case (`agent_cmd.rs:262-266`, `:451-467`) and its human lines on stderr (`say`, `agent_cmd.rs:258-260`). For `asserted`: "The owner confirmed that launch <id> has ended.", exit 0. For `already_exited` with `confirmed_within_deadline: false`, the late-proof line (`agent_cmd.rs:320-329`, exit 4, `ExitCode::Timeout`) becomes "The process had already ended, but this stop did not confirm its end within 5 s (its end may have been confirmed by the owner's assertion).", exit 4 as in 10a1, since the result does not say which.

**One confirmation per launch.** The intent runs in the writer's job, which re-reads `L`; the writer runs one job at a time, so of two assertions for `L` the second reads it confirmed and is answered `asserted` with nothing written. The key backs this: a second `launch_death_confirmed` for `L` from another command differs in `command_id` and is `KeyConflict`. A probe never writes one (§2.1 rule 1). After the assertion, `resume` and `close` pass their death check (sup §2.3 step 3, "Close"); a resume of an unbound launch then still answers `no_session` (`ops.rs:374-385`). Whether worktree removal treats the launch as in use is PR 16's check (mvp §2.9), which reads `death_confirmed`.

**CLI.** `chaldea stop <thread> --assume-dead [--launch <id>]`; `--launch` requires `--assume-dead`. With `--launch`, it sends `StopArgs { thread_id, expected_launch_id: id, assume_dead: true }`; refusals print as 10a1's do. Without `--launch` it sends nothing (the preview).

**Preview** (Neon r3 #3, r1 H1; sol r1 M2–M4), under one 30 s cutoff for every request (`cli::client`'s deadline rules):

1. `client::discover` → the serving daemon's record (`lifecycle/files.rs:145-156`) and its `instance`, a UUID per run (`startup.rs:114`, `:185`); `GET /api/threads/{thread_id}` → the current `LaunchInfo` (sup §2.8, `sync.rs:153-160`: `pid`, no start time). No launch or a launch not exited: print that and exit 0.
2. Page backward through `GET /api/events?stream_id=thread:<thread_id>&before_seq=<b>&limit=<n>` (the stream's text form, `ids.rs:241-268`), from `b` = 9007199254740991 (accepted, `sync_api.rs:320-321`), each next `b` the page's lowest seq. Backward pages are bounded by count only (`readers.rs:393-420`), and the client refuses a body over 1 MiB (`client.rs:13-14`, `:230-232`): `n` starts at 16 and is halved, at the same `b`, only after the client's body-limit error (`client::is_body_too_large`; today it is an `InvalidData` error like every other protocol error, `client.rs:230-232`, `:243-245`), down to 1. Every page's `stream_id` must be the requested one, and the first page's `epoch` must hold on every later page (`EventsResponse::Replay`, `sync.rs:252-261`). Keep `L`'s `launch_evidence` and `launch_death_confirmed` events and its `launch_exited`. Stop at `L`'s `launch_exited`, since every evidence event follows it (§2.4); for `unknown_after_crash` go on to `L`'s `launch_reserved` for its `agent` and `recorded_at`. Stop also when `has_more_before` is false or a page is empty. After the scan, `client::discover` and `GET /api/threads/{thread_id}` again: the same serving `instance` and the same launch, exit reason, and death state as in step 1, else the scan is interrupted (a restart, an assertion, or a resume in between; sol r2 M2). Every request of steps 1 and 2, a retry included, is bound to step 1's run: before it is sent and after its response is adopted, `client::discover` must still name that `instance`; another run serving ends the read with "the daemon restarted during the read", and no daemon serving after a response with "the daemon stopped during the read" (in step 1, exit 1; during the scan, an interrupted scan), so no response from another run is used. The scan is **complete** when it reached its stop event and the re-check held; else (`has_more_before` false first, an error, an epoch or stream change, a single event over 1 MiB, the re-check, the cutoff) it is **interrupted**.
3. Print the launch id, exit reason, and death state (for a confirmed launch, its method); the recorded identity: the pid from `LaunchInfo` with the start time from the latest evidence that names that pid, or "start time: not read by this preview (recorded in `launch_started`)"; `launch_exited.failed_start`, when present, as "identity recorded at the failed start" (a probe of it is among the evidence, RD1); each evidence event in seq order with its `recorded_at`, source, each identity (pid, start, `observed` and its class from §2.4's table), each `unchecked` item's meaning, and for a `probe` whether `probe_run` equals the serving `instance` ("this daemon run") or not ("an earlier daemon run"); evidence after a `launch_death_confirmed` under that confirmation. Then, by what is missing: a prober candidate (RD1: a `daemon_restart` launch, or a `spawn_failed` launch whose `failed_start` names a start time) with no `probe` from this run: "The running daemon has not recorded a probe of this launch: it may still be running, or it was skipped (see the daemon log)."; a `stopped`, `exit`, or `spawn_failed` launch with no evidence after a complete scan: when its end was proven (`launch_exited.death_confirmed`, or a confirmation by a method other than `owner_asserted`), "The launch's end was proven when it exited, so no check report was needed.", else "No check report was recorded for this launch (it ended under a daemon version that did not record one)."; `unknown_after_crash`: "No process identity was recorded" with the agent and `recorded_at`. An interrupted scan prints "The history could not be read completely (<reason>); the list above may be missing evidence." Last, for an unconfirmed launch: after a complete scan, the command `chaldea stop <thread> --assume-dead --launch <L>`; after an interrupted one, no command, but "Run `chaldea stop <thread> --assume-dead` again to read the evidence before confirming that this launch has ended." Exit 0 for a complete scan; 1 for an interrupted one.

**`death_unconfirmed` text** (sup §2.2). The tail "This version cannot resume or close this thread. Its history is kept, and new threads can be started." becomes "To review what was checked, run `chaldea stop <thread> --assume-dead`; once you have made sure its processes ended, confirm with `--launch <id>`. Its history is kept, and new threads can be started." The reason lines stay.

## 3. Decisions

Each compares gain, loss, reversibility, and cost. "Public" marks a decision visible to users or clients.

**RD1. The prober's candidate set** (sol r3 #2a, Neon r3 #2).

| Option | Gain | Loss | Reversibility | Cost |
|---|---|---|---|---|
| A. The launches this start's reconciler marked | none to read | a second crash after the reconcile commit and before the probe leaves the launch unprobed for good; the reconciler's job returns only a count (`lifecycle/mod.rs:170-174`) | — | small |
| **B. Every unconfirmed `daemon_restart` launch with a pid, and every unconfirmed `spawn_failed` launch whose `failed_start` names a pid and a start time, read after `attach`, in each start that reaches its probe** | survives any number of crashes; no state beyond the projection | one evidence event per such launch per start until the owner asserts (L-8); one read per identity already gone | narrowing to C later is local | small |
| C. B minus launches whose last probe observed every identity dead | fewer events | needs the evidence read per launch or a new projection column, a cross-start state the probe does not need (a dead identity stays dead, so B's repeat costs one read) | — | medium |

**Adopted: B.** A failed start's child is in the set because a recorded identity alive after the restart fails P-18 (RD9): the kill at the failed start could not prove it ended, and no other path signals it again. Its evidence source is `probe`, as for a `daemon_restart` leader, and its unchecked scope is the host's (§2.4). The set takes the recorded text as it is: an identity `kill_recorded` refuses is probed without an OS call and recorded `invalid`, rather than left out by a second validator. A start that skips the probe (read timeout, slot stall, shutdown, a lost record) leaves the launch for the next start; the preview shows that the running daemon has no probe of it (§2.5).

**RD2. Probe on `stop`, and the probe lock** (sol r3 #2b).

| Option | Gain | Loss | Reversibility | Cost |
|---|---|---|---|---|
| A. The prober and a `stop` both probe, serialized by a per-launch probe lock | an on-demand re-probe | a lock whose entry must outlive waiters and slow blocking tasks, a third `stop` outcome and a `recorded_gone` field (an earlier draft's, never built), an op path, and a namespace for client ids in keys | the flag and outcome stay once published | large |
| **B. Only the prober probes; `stop` without `--assume-dead` keeps 10a1's `death_unconfirmed`** | no lock: one prober per start probes each launch once, and RD3's token keeps two daemons from probing at once, so probes of a launch never overlap; no wire change for plain `stop` | a probe whose record failed, or an identity left `alive`, waits for the next start (L-5, L-6) | A can be added later as a new outcome | small |

**Adopted: B.** A probe unlocks nothing (owner decision), so an on-demand probe only refreshes what the owner reads; restarting the daemon gives the same.

**RD3. Probe admission, slot, and lifetime** (sol r3 #2b, sol r1 H1). Adopted: a `TrackToken` from `Tracker::admit` and an owned semaphore permit, both moved into the blocking closure; both are dropped when the closure returns, unwinds, or is dropped unrun, the token through `ProbeAdmission`'s drop, so it counts the worker exactly while it can signal (§2.3 step 3.4). Rejected: a token released only by `TrackToken::release` on return (a panicked probe would keep every later shutdown of that run from `Clean`); a permit held by the awaiting task (released at a join timeout while the blocking work runs on, so more than 4 run); a separate probe counter the participant also waits on (a second count for the same lock rule, which reads one count today); checking `Tracker::accepting()` without a token (a snapshot: shutdown can close admission after the check, and a probe still signalling would not hold the lock).

**RD4. Evidence shape** (sol r3 #6). Public.

| Option | Gain | Loss | Reversibility | Cost |
|---|---|---|---|---|
| **A. One event kind; per identity an `observed` value in three classes; a list of what was not covered; the probing run's identity** | the owner sees what was read dead, read alive, or not read, what no read covered, and whether the running daemon probed; an owned close with an empty survivor list still shows `tree_unproven` | a new public kind and enums | additive values later | small |
| B. Fields on `launch_exited` | no new kind | a probe happens after the exit and once per start | — | small |
| C. `survived` for every identity not shown dead (the earlier text) | fewer values | merges alive, refused, and not received; shows a proven-dead failed start's leader as a survivor | — | small |

**Adopted: A.** Public: the kind `launch_evidence`, its payload, and the values of §2.4. The run is identified by the discovery record's `instance`, a UUID per run that exists before `attach` (`startup.rs:114`) and reaches the supervisor as `BuildCtx.instance`. Rejected: the daemon process's `(pid, start_time)` (wall-clock stamps that a clock step back can repeat, L-4); the record's `started_at` (rewritten at step 13, after the prober can record, `startup.rs:547`, `:759`). Would change if the owner wants raw kill reports instead; they stay in the log.

**RD5. Idempotency keys** (sol r3 bullet). Public. Adopted: `launch:<L>:evidence:spawn_failed`, `launch:<L>:evidence:close`, `launch:<L>:evidence:probe:<attempt>` with a server-minted UUID, and the assertion under the existing `launch:<L>:death_confirmed`. RD2 leaves no client-supplied id in a key. Rejected: `probe:<command_id>` beside the UUID in one namespace (a client id could equal a server one); a per-start counter (needs a stored start number).

**RD6. Where the assertion runs, and what a confirmed launch answers.** Public: `StopArgs.assume_dead` (omitted when false), `StopOutcome::Asserted` (only for `assume_dead` requests), the method `owner_asserted`, the CLI flags, and a plain stop of an asserted launch answering `already_exited` with `confirmed_within_deadline: false`. Adopted: in the `stop` intent's job, with no op: it is one store transition the writer serializes. Rejected: a `LaunchOp` (no process work to own); a separate command name (a new grant row in `MVP_COMMANDS` for one branch of `stop`); `confirmed_within_deadline: true` for an asserted launch (an assertion proves nothing within mvp P-3's 5 s); `asserted` to a plain stop (a 10a1 CLI cannot decode it, `command.rs:178-186`); response negotiation by client version (a mechanism for one value). The adopted plain-stop answer keeps 10a1's exit 4 and changes only the new CLI's wording. On a concrete input: `stop` with the same args as before has the same canonical arguments and behaves as in 10a1 (a stored 10a1 receipt replays), and a plain stop of an asserted launch reports no timed proof; an old daemon refuses `assume_dead: true` as an unknown field (400 `bad_args`); a client sees `asserted` only when it sent `assume_dead: true`.

**RD7. Preview scan range and page size** (Neon r3 #3, r1 H1; sol r1 M2). Adopted: backward from the head to `L`'s `launch_exited` (to `launch_reserved` only for `unknown_after_crash`), 16 events a page, halved on the client's body-limit error; the preview bound to one serving run by the instance re-check. Rejected: down to `launch_reserved` for every launch (pages through the whole session history); a fixed large page (a few inline 64 KiB events exceed the CLI's 1 MiB body); a fixed `limit` of 1 (one round trip per event in the common case); a server-side byte bound for backward replay (a change to `decide_replay` for one client); a new evidence route (a route and a grant for a read the stream already serves). Public: none beyond the CLI's output.

**RD8. A29 hand-off** (sol r3 bullet, Neon r3 #4).

| Option | Gain | Loss | Reversibility | Cost |
|---|---|---|---|---|
| **A. Existing records (launch id, agent, `recorded_at`); the finder's conditions as `launch::a29_candidate`, matching the agent's executable file name and saying the path was not recorded** | no new field; the rule is tested once, where it is decided | a resolved program whose file name differs from the agent's (a PR 14 shim resolution) is missed: its suspended child stays until the owner ends it, and it never runs | B can be added later | none |
| B. `launch_reserved` gains the resolved program path | exact image match | a new public field on every reservation | additive | small |

**Adopted: A.** Would change to B if PR 14's program resolution yields file names other than the agent's.

**RD9. P-18's survivor policy** (sol r3 #1, sol r1 H2). **Decided by the owner (2026-11-26): (b).** mvp P-18: no surviving old process after a daemon kill except the documented macOS `setsid` limit (spike §4.6). After a crash the new daemon owns no old session (pty-unix §2.4 "Ownership is a precondition"), so it signals only recorded identities (§2.2), and the MVP records one: the leader (sup §2.4 "`extra` and its source").

Under (b), P-18's exception after a crash is the processes of the old launch for which no usable `(pid, start_time)` was ever recorded, reported as the launch's unchecked scope:

- **macOS:** members of the old session that survived the PTY hangup (a same-session child that ignores SIGHUP, such as a `nohup` command an agent started), and the child an A2 crash left running with no identity (`unknown_after_crash`, `no_identity`).
- **Windows:** processes outside the launch job without a recorded identity: A29's suspended child; and descendants a CLI started outside the job (`docs/architecture.md:62`: in the spike a Codex `pwsh.exe` was outside the job before stop and died at the owned job termination; its fate after a crash is not observed). Job members are ended by `KILL_ON_JOB_CLOSE` when the old daemon exits (pty-windows §4 row "Daemon restart"), unobserved.

A recorded identity still alive after the restart is not in the exception: P-18 fails for it, and the evidence reports it. This includes the child of a suspended-branch assignment failure whose termination was not confirmed: its pid and start are recorded in `launch_exited.failed_start` (`windows/mod.rs:963-975`, `unassigned(Some(start))`; `ops.rs:208-215`), the launch is `spawn_failed`, its `spawn_failed` evidence lists it `unresolved`, and each start that reaches its probe signals it by verified identity (RD1). 10a2's evidence criterion (PR10a2-P-1) and P-18 (PR10a2-P-4) are judged separately: P-4 compares identity-matched witnesses recorded before the crash with their state after the probe, and its verdict is pass, fail, or inconclusive (a witness whose start cannot be read; a launch without an identity, which no probe covers).

| Option | Owner gains | Owner loses | Reversibility | Cost |
|---|---|---|---|---|
| (a) Keep P-18; mark it unmet until a design finds and ends such members after a crash | P-18 stays the full requirement | P-18 fails on macOS whenever such a member exists, and on Windows for any unrecorded process outside the job, with no path to pass in the MVP | text only | none |
| **(b) The exception above, reported as unchecked scope** | P-18 states what 10a2 does; the owner sees the scope in the preview before asserting, and nothing unlocks without the assertion | such a process keeps running until the owner ends it; "reported" names a scope, not pids | text; (c) narrows it later | none |
| (c) Record members while owned: a periodic owned census per live launch (macOS: one clean owned pass proves membership; Windows: the job's member list), recording members as identities in a new event; the prober adds them | long-lived members (MCP servers, a `nohup` server) are ended and observed after a crash | a member started after the last snapshot stays unchecked (a sampling gap, whatever the period; requiring two snapshots only filters short-lived members); a census per launch per period (a pass is a few ms over ~1 000 pids, pty-unix §2.5); an event per membership change; on Windows job members are already ended by `KILL_ON_JOB_CLOSE`, so it adds observation only, and descendants outside the job are not in the list | additive event kind, kept in history once written | medium |
| (d) A census of session `L` bracketed by two verified reads of the recorded leader alive | finds candidates while the leader survived the hangup | no help when the leader died (then sid `L` can name another session); signalling what it finds needs its own attribution design under the unowned-process rules, and brings the census SD3 rejected into the unowned path | reversible | medium |

**Adopted: (b)**, the owner's decision. The owner decision of 2026-11-25 already keeps a crashed launch from unlocking without the owner's assertion, so the harm left is a process running on, which the preview names. (c) is additive to this design: the prober already takes a list of identities, so it can follow as its own PR. **What would change it:** PR 15/23's P-18 run finding a survivor inside the exception that the owner treats as a release blocker (an MCP server or a backgrounded command that ignores SIGHUP; a Codex descendant outside the job on Windows): then (c) is scheduled.

**RD10. `kill_recorded` as its own loop.** Adopted: §2.2 over `OrphanOs` / `ProcessOs`, neither with a list, group, or job call. Rejected: `kill_tree` with an unowned `Os` (its rounds list every pid and cover descendants by parent, a census in all but name, `unix/kill.rs:595`); the sid scan of mvp §4 (sup SD3); `host::send_stop` (`host/mod.rs:911-956`, TERM only, the daemon's own stop target); `JobOs` on Windows (its real implementation holds a job handle, and its job methods would be stubs).
