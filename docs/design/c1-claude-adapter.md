# C1: Claude Code Adapter (lite) and the Rescue Read Surface

Status: design for mvp §4 row C1 (carries PR 12's Claude fixture checks and PR 13). It makes a real Claude Code launch bind, take prompts, open and close approval cards, record assistant text, and resume, and it adds the external agent's read surface (`GET /api/threads/{thread_id}/screen`, `chaldea inspect`). Contracts it builds on: mvp §2.1 transcript cursor rules, §2.3, §2.7, §2.9, §2.10, §4 C1 obligations (`mvp-design.md:476-477`); `docs/design/hook-ingest.md` §4 row 13, D2, D3; `docs/design/supervisor-send.md` §2.4, §2.5, L-13; `docs/design/input-encoders.md` §2.4, D4; `docs/design/event-store.md` §2.3. Identifiers marked *new* do not exist at main.

## 1. Mechanisms

At main a Claude launch already gets `--session-id <launch_id>` or `--resume <session>` (`core::launch::plan`), the hook env, the session-id binding rule, the bracketed paste send and gate, card state effects in `SupervisorHooks`, `append_transcript` with its binding and cursor checks (`store/write_tx.rs:676-700`), and `LiveLaunch::snapshot_before` (`supervisor/live.rs:219`). The decoder is the single `NoDecoder` (`supervisor/send/mod.rs:425`), so a real Claude never binds (supervisor L-4).

- **Hook injection.** A fallible startup step writes `<state_dir>/claude-settings.json` by rename before serving; a failure fails the start with `FailReason::StateDir` (`lifecycle/mod.rs:277`), since `Components::build` cannot fail (`supervisor/components.rs:63`). It registers `SessionStart`, `UserPromptSubmit`, `Stop`, `PermissionRequest`, `PreToolUse`, `PostToolUse`, each running `<current_exe> hook-emit claude`, quoted for the hook shell of each OS. Every Claude launch gets `--settings <that path>` (`LaunchInput::claude_settings`, *new*).
- **CLI version.** Spawn and resume run `claude --version` before the reservation, as the workspace probe runs git (`TrackedChild::spawn` under the spawn lock with a deadline, `supervisor/workspace.rs:118-185`), with one 5 s bound covering the child's exit and the read of its stdout (at most 4 KiB, read while it runs, so a descendant holding the pipe cannot extend it); the result fills `launch_started.cli_version` (`null` today, `supervisor/ops.rs:557`), so hook `raw_unknown` events carry it (`hook/route.rs:104`). A probe that fails or times out leaves `null` and the launch proceeds.
- **Decoding.** `ClaudeDecoder` (*new*) behind a per-agent dispatch (*new*; Codex keeps `NoDecoder` until X1). It is split into a pure `parse(event_name, json)` (*new*: input and local state only, no `ReadTx`, no lock) and the store-reading rest. `PreToolUse` → `tool_activity { started }`, `PostToolUse` → `tool_activity { completed }` plus card evidence.
- **Recoverable panics.** `lifecycle::panic::recoverable` (*new*) runs a pure closure under `catch_unwind` with a private thread-local flag, set and restored to its previous value by an RAII guard, that makes the panic hook log its line without `request(StopCause::Panic)` (today the hook requests it first, `lifecycle/panic.rs:58-61`). It wraps only `parse` (C1b) and the transcript line parser (C1c), never a store read, a lock, or an event application. A caught panic yields `raw_unknown` `schema_mismatch` with the exact bytes.
- **Card resolution.** `HookFact::CardEvidence` carries `tool_name`, `tool_input`, and an optional `tool_use_id` (internal; `supervisor/send/hooks.rs:392` matches only `tool_use_id`). A `PostToolUse` resolves a card `ran` only when its receipt ordinal is above the turn watermark and above the card's (the card's delivery, `approval_id` = its `emit_id`), and exactly one open card of the launch has an equal `tool_name` and canonical `tool_input`. Anything else leaves the card for the turn boundary. C1 adds no other card rule.
- **Stale cards.** A `CardOpened` whose receipt ordinal is below the turn watermark appends its `approval_requested` and, in the same job, `approval_resolved { superseded }`, with no `ApprovalOpened`, and returns `TurnMark::Other` so `SendLaunch.cards` keeps no entry (`hooks.rs:387`, `probe.rs:148-153`). Its card key answers `card_closed`. This removes supervisor-send L-13 case f, where a card committed after a later `Stop` stayed open and its key reached the PTY.
- **Transcript tailer** (`TranscriptTailer`, *new*, one per live bound launch with a path; joined by the supervisor's shutdown participant, `supervisor/components.rs:158`). Every 1 s it reads on a blocking task, never on the store writer or under the op lock, through `chaldea_pty_runtime::file::open_regular` (*new*: absolute path only; Unix `O_NONBLOCK` open; Windows device and pipe namespaces refused before the open; regular-file check and `file_id` on the opened handle, read through it; Windows FFI in `windows::sys`, `pty-runtime/tests/lints.rs:250-253`). Lines are parsed as a stream, skipping values it does not keep, so line size never bounds parsing. A known type with assistant text → `assistant_message`; another known type → no event; an unknown `type` → `raw_unknown` `unknown_event`; not JSON → `unparseable`; JSON of the wrong shape → `schema_mismatch`. After `launch_exited` it reads once more (up to three polls on I/O errors, then it ends with a log line; the bytes stay in the file for the session's next launch) and keeps trailing bytes without a newline as `raw_unknown` `partial_line` (mvp §2.1). `NotFound` and I/O errors retry at the next poll; `StaleCursor` re-reads the cursor; `StaleBinding` ends the tailer.
- **Continuity** (the `Continuity` text, `store/annex.rs:45`): `sha256:<hex>` over bytes `[0, offset)`. While its handle stays open the tailer extends a running digest with the bytes it reads. It re-reads and verifies the whole `[0, offset)` at every open (start, daemon restart, resume, rebuild, reopen after an error), and each poll it checks, before any cursor advance (a batch with `lines: []` included), that the path still names the handle's `file_id` and the size is not below the cursor. A failed check discards the batch read from the old offset, commits a new generation alone at offset 0 (`sha256` of no bytes; `GenerationWithLines`, `store/write_tx.rs:720-730`), and re-reads from 0; earlier events stay in history, and lines common to both files appear again under the new generation.
- **Large content.** Bytes above `MAX_BLOB_BYTES` (64 MiB, `store/content.rs:17`) are stored as one blob in ordered internal parts: `Content` keeps one `BlobRef` with the whole content's SHA-256 and size, and `GET /api/blobs/{sha256}` serves the parts in order. This applies to every stored value over the cap: `raw_unknown` of any reason (decoder-panic bytes included) and assistant text. Store side (*new*): a migration V4 adds `large_blobs`, `large_blob_parts`, and `large_blob_refs` with immutability triggers and recreates `events_blob_refs` (`store/schema.rs:170`) to accept a reference in either refs table; `blobs` and `blob_refs` are unchanged (no table rebuild under `foreign_keys`, `store/open.rs:68`). `check_blob_ref` (`store/content.rs:270`) accepts a size above the cap for a large blob; previews read part 0. Public contract unchanged.

## 2. Acceptance criteria

**FC** = FakeCli/FakePty test in CI on macOS and Windows; **M1** = dogfooding with real Claude on macOS (Windows at M2), rows of mvp §6.1 and the evidence list of §4 (`mvp-design.md:478`).

| ID | Criterion (EARS) | Check |
|---|---|---|
| C1-1 | When a Claude launch is reserved, its argv shall carry `--settings <state_dir>/claude-settings.json` and either `--session-id <launch_id>` or `--resume <bound session>`, and the user's settings files shall stay byte-equal. | FC (`plan`; settings content; executable paths with spaces and quotes on both OSes; write failure → `state_dir`); M1 P-1 (a user skill, hook, and permission rule still work) |
| C1-2 | When real Claude starts in a trusted folder, its `SessionStart` shall bind the launch, and with intake facts present, record `readiness_observed { session_start }`. | FC; M1 evidence: registered, fired, and durably ingested events listed apart |
| C1-3 | For every committed fixture, `ClaudeDecoder::decode` shall return the fixture's expected fact and events (`tool_activity` started and completed included); a fixture of a registered event decoding to `Other` with no event shall fail. | FC (`decode` directly) |
| C1-4 | If a decoder panics on a hook payload or transcript line while the production panic hook is installed, then the daemon shall commit the bytes as `raw_unknown` `schema_mismatch`, request no stop, and serve the next request. | FC (C1b: hook; C1c: line; and a panic right after the recovered region, outside it, still requests the stop) |
| C1-5 | When each corpus prompt is sent through `chaldea send` or `spawn --prompt`, Claude shall record it once, equal to the expected form the fixture states; the input shall end `acked`, with exactly one submit. | FC (captured records against literal expected forms; `prompt_matches` negatives); M1 P-6 |
| C1-6 | If an input is not acknowledged within the ack window, then it shall end `unconfirmed` with attention, and no second submit shall follow. | FC (10b tests with `ClaudeDecoder`); M1 P-15 |
| C1-7 | When `PermissionRequest` arrives, a card shall open and the turn shall be `awaiting_approval`; a `PostToolUse` shall resolve it `ran` only under §1's rule; the turn shall return to `running` only when the last open card resolves; `Stop`, a bound `UserPromptSubmit`, or exit shall close the rest; a card received before a committed later turn boundary shall be closed when it opens, and its card key refused with `card_closed`. | FC (case f: `Start(1)`, `Card(2)`, `Stop(3)` committed 3, 2, 1 → closed, key `card_closed`; control: a card received after its turn's start → open, key written; a previous turn's `PostToolUse` committed after the next turn's equal card → no `ran`; two cards, resolve one then the other) |
| C1-8 | While a launch is bound with a transcript path, the tailer shall append each assistant text line with its cursor advance in one transaction, emit nothing for other known lines, keep unknown and unparseable lines as `raw_unknown`, and start a new generation whenever §1's continuity is disproved, including after a cursor rebuild. | FC (real files in the OS temp dir: append; same `file_id` and tail with a rewritten prefix, found at the next open and across a rebuild; truncate below the cursor with `lines: []`; replace; lines over 64 MiB, valid and unparseable, stored whole and downloaded equal, with the next line ingested) |
| C1-9 | If the bound path is relative, a FIFO, a device, or not a regular file on the opened handle, then the tailer shall read nothing, and the supervisor and store shall keep running. | FC (FIFO on macOS; `\\.\` path on Windows) |
| C1-10 | When a launch exits, the tailer shall read the rest and keep a trailing partial line as `partial_line`; when the owner resumes after confirmed death, Claude shall start with `--resume <session>`, bind the same session, and the tailer shall continue the same generation from the cursor. | FC (C1b: rebind; C1c: final read, cursor resume); M1 P-18 |
| C1-11 | When a token that can read a thread requests its screen while the thread has a live session, the daemon shall answer `ScreenResponse` and append no event. | FC (route × token matrix, CL-15; CJK, combining, empty rows; the size bound with escape-heavy rows (`"`, `\`, controls); each error of D1) |
| C1-12 | When `chaldea inspect <thread>` runs, it shall print the thread's state, attention, launch, session, non-terminal inputs, open cards, recent events, and screen, or with `--json` one `InspectOutput`, and exit per D2. | FC (CLI against a test daemon; a snapshot over the cap) |
| C1-13 | While Claude stalls on a startup prompt before `SessionStart`, the thread shall carry `session_start_timeout` and the daemon shall write no byte. | FC (FakeCli `stall`; early hooks with DECSET 2004 on: no write before evidence) |
| C1-14 | If a bound launch receives a `SessionStart` with another session id, then it shall be `raw_unknown` `foreign_session` and the binding shall stay. | FC (`/clear` and in-session `/resume` fixtures, their `source` and id) |

## 3. Decisions

**public** marks public contract.

| # | Decision | Alternative rejected |
|---|---|---|
| D1 | **public** `GET /api/threads/{thread_id}/screen`: a `ROUTES` row (`owner_pr` 13) with `OriginRule::AbsentOrMatching`, credential `READERS`, `Action::ReadStream`, the object check of `GET /api/threads/{thread_id}` (`http/sync_api.rs:234`) before any live lookup (owner and rescue all, agent self+, else 404), `no_query` (400 `bad_query`), and `no-store`. `snapshot_before` returns a typed outcome (*new*): no session → 409 `no_live_launch`; lock contended or not copied in time → 503 `busy`, `retry_after: 1`; VT failed → 500 `internal`; its deadline is `min(now + 250 ms, request deadline)`. Body `ScreenResponse` (*new*, `core::sync`, ts-rs and JSON Schema): `{ thread_id, launch_id, cols, rows, cursor: VtCursor, modes: VtModes, lines, truncated }`; `lines[i]` = `Line::text()` (`pty-runtime/src/snapshot.rs:79`: wide tails dropped, combining characters kept, trailing spaces trimmed); `cursor` in cell coordinates. Size bound on the serialized JSON body, ≤ 512 KiB (half the CLI's 1 MiB cap): `lines` always has `rows` entries, `lines[i]` is screen row `i`, and when the body would exceed the bound each row is cut at a UTF-8 character boundary so its JSON-escaped form fits `(512 KiB − 4 KiB) / rows`; `truncated` is true when any row was cut; `cursor` is unchanged. | Owner only: an orchestrator could not diagnose its own children; the route only reads. The `vt_snapshot_taken` cell grid: callers would rebuild text. |
| D2 | **public** `chaldea inspect <thread> [--json]` with the owner token: reads the thread snapshot through `GET /api/events` with `after_seq` = `MAX_SAFE_INTEGER` (`core/src/lib.rs:35`; the documented `cursor_ahead` fallback) under a 16 MiB body cap (the client default is 1 MiB, `cli/src/client.rs:14`), then the screen. Summary, attention, inputs, and cards come from that one snapshot. A snapshot read that fails with a body over the cap or a timeout (the daemon answers 408 when building it reaches the request deadline) falls back to `GET /api/threads/{thread_id}` (`ThreadSummary`); the output then lacks the attention causes (count only), session, inputs, cards, and recent events. `InspectOutput` (*new*, `core::sync`, ts-rs and JSON Schema): `{ thread_id, snapshot, summary, screen, snapshot_error, screen_error }`, errors as `ErrorBody`: the daemon's own, or for a client-side failure `payload_too_large` (over the cap), `request_timeout`, or `internal` (transport or decode). The screen's `launch_id` is checked against the launch read (`snapshot.launch`, or `summary.launch` on the fallback); a mismatch gives `launch_changed` and no screen. Exit (`ExitCode`, `lifecycle/mod.rs:259`): 0 when the snapshot or the summary was read, 1 when neither was (unreadable thread, daemon unreachable), 2 usage, 4 the summary read timed out. | A snapshot query parameter or route: wire surface for what the fallback returns. Raising the client's global cap: every command would accept 16 MiB. |
| D3 | **public** Claude argv gains `--settings <state_dir>/claude-settings.json` (`argv_digest` changes). One file per daemon start. | One file per launch: cleanup at exit and after crashes for identical content (per-launch values travel in env). |
| D4 | Registered Claude events are the six of §1; C1b updates mvp §2.7's hook-events row and hook-ingest §4 row 13 to match. | All eight: no event kind carries `SessionEnd` or `Notification`, so every one would be `raw_unknown`; Claude hashes no hook list, so adding one later costs nothing. |
| D5 | Session switches (hook-ingest D2): a launch keeps its first binding; a later same-session `SessionStart` (`compact`) stays `raw_unknown` `unknown_event`. | Following the new session: a repeatable `session_bound`, a gate turn start, a tailer generation, and a trigger migration, for a case the owner recovers with a new thread. |
| D6 | Claude keeps rule `SessionId` (hook-ingest D3); M1 records the observed hook ancestry. A nested Claude resuming the launch's session id is taken as the launch's own (limit stated in hook-ingest §2.5). | `Ancestry`: unverified on real hosts. |
| D7 | A caught decoder panic is `raw_unknown` `schema_mismatch`. | A new reason `decoder_panic`: a public enum value the daemon log already distinguishes. |
| D8 | The expected form is fixed from macOS captures as literal strings, and C1b narrows `prompt_matches` for Claude to the captured transforms (input-encoders D4), with a negative case per dropped transform. `prompt_matches` takes no OS: spike C-1 (Windows) agrees on NFC only, so if X2's P-6 shows Windows differs on TAB or the paste wrapper, the matcher gains an OS parameter then. | Keeping every subset: masks a Claude change in rendering. |
| D9 | No `vt_snapshot_taken` when a card opens. | Recording one: `interpret` is data only; the screen route shows the live dialog. |
| D10 | Continuity as §1. | The last 4 KiB only: misses a rewritten prefix with an equal tail. Re-hashing the prefix on every changed poll: O(n²) reads over a session. |
| D14 | Values over 64 MiB as internal parts of one blob (§1). | Truncating with a marker: a second exception to the `raw_unknown` verbatim rule (AGENTS.md invariant 3). Halting the tailer at such a line: stops ingestion for that session for good. |
| D11 | The CLI version from a bounded `claude --version` per launch (§1). | `null`: leaves arch §2's "`raw_unknown` + CLI version" unmet. |
| D12 | `GET /api/adapters` gains no readiness column. | Adding it: no client acts on the mode; a field is additive later. |
| D13 | `open_regular` lives in `chaldea_pty_runtime::file`, as `process::ancestry` does. | `cfg` code in the daemon. |

C1a fixes the canonical text where it differs from code in its area: mvp §2.5's route table entry, `input resolve --outcome delivered\|dismissed` (`cli/src/args.rs:138-159`; mvp §2.3 says `--delivered \| --dismiss`), and readiness mode `none` vs `ReadinessMode::OwnerOnly`. C1b fixes mvp §2.7, hook-ingest row 13, supervisor-send §2.5 (per-agent decoder), PR10b-CL-13 (`card_committed_after_later_stop`), PR10b-CL-23 (`card_between_stale_start_and_stop`), and L-13, mvp §2.10 (a bound `UserPromptSubmit` also closes cards, `supervisor/send/hooks.rs:327`), and arch §2's CLI version. C1c updates event-store §2.4–§2.5 for large blobs.

**L-13 after C1** (C1b writes it there). Stale-at-open closes case f. Card order is receipt order, and receipt order is not firing order: if a turn's `UserPromptSubmit` is received after the turn's `PermissionRequest` and commits first, the legitimate card is closed at open while its dialog waits; in the other cases of L-13 a card can stay open after its dialog ended until the boundary. Either way no byte is misdelivered: the owner sees `card_closed` (or `key_not_written`) on the card key and answers the dialog through the attach WebSocket and the terminal view (T1, T2).

## 4. Fixtures

Captured by hand: with injection in place and `NoDecoder`, every hook arrives as `raw_unknown` with its exact bytes; the developer exports them from `GET /api/events`, scrubs them, and commits `<Event>-<n>.json`, an allowlisted `.meta.json` with the expected fact (and for prompts the literal expected form), and transcript excerpts. Cases: a plain turn; the corpus of input-encoders §2.4 (compatibility ideograph, spaces and LF at the ends, TAB, wrapped body with TAB and marks, DEL, C1, leading `/`, `!`, `#`); an approved and a denied permission; a subagent tool call; `/clear`, in-session `/resume`, `/compact`; a resume. `fixtures/claude/<cli-version>/README.md` records, per version (mvp §4 C1 fixture checks): the payload fields per event, `PermissionRequest` order against `PreToolUse`, `prompt_id` presence, `Stop` continuation (`stop_hook_active`), the measured settle interval, and whether any post-decision signal exists. A test fails on a home-directory shape (`/Users/`, `/home/`, `C:\Users\`), a token-shaped string, or a prompt outside the corpus.

## 5. Risks

| Risk | Detection | If accepted: the limit, and why the purpose holds |
|---|---|---|
| `SessionStart` fires before the folder-trust prompt is answered, so readiness opens the gate while the dialog (default "No, exit") is up. | M1 P-12 in a fresh untrusted folder; fixture event order. | Not accepted: if observed, the Claude rows switch to `ReadinessMode::OwnerOnly`. The launch is then bound, so `session_start_timeout` does not appear; a queued prompt raises `input_gate_timeout` after 60 s and the owner runs `ready`. |
| Readiness is missing at bind when intake facts are missing (`hooks.rs:212-220`). | `inspect` shows a bound launch without evidence. | Fail-safe: the gate stays closed; the owner runs `ready`. |
| `--resume <session>` starts a new session id. | M1 P-18; `session_start_timeout`; `foreign_session`. | Resume then needs a fresh thread; nothing is written to an unbound launch. |
| Claude's hook shell on Windows does not run the quoted command. | M2 P-1, P-6: `session_start_timeout`. | macOS is unaffected; the fix is the settings file's command string. |
| After `/clear` or in-session `/resume` the thread keeps the old session (D5): the tailer stays on the old transcript, `resume` passes the old session, and an owner `ready` still passes, so a send lands in the new session. | `foreign_session` in `inspect` and the W2 count. | That send's `UserPromptSubmit` is `foreign_session`, so the input ends `unconfirmed` and is never resent; no readiness comes from the new session. The owner starts a new thread. |
| A denied permission fires no `PostToolUse`, so its card stays open until the turn's boundary. | M1 P-16. | A second card key is refused once any human unit followed the card (CL-13); the turn's `Stop` closes the card. |
| A denied card and a later equal call that runs without its own card: the call's `PostToolUse` marks the denied card `ran`. | None at run time. | Only the outcome label is wrong: the card would close at the boundary anyway, and no byte is written. |
| A resume reserved before the old tailer's final read makes that read `StaleBinding`. | Tailer log. | The new launch binds the same session and path (Claude keeps one file per session), so its tailer reads those bytes from the cursor. |
| An in-place rewrite of already-read bytes while the handle stays open and the file keeps growing is found only at the next open. | The next open's verification. | Claude only appends; a rewrite through truncation shows as a size below the cursor at the next poll. |
| A value over 64 MiB is held in memory whole until its event commits. | Tailer log of the line size. | One such line at a time, bounded by the line; no Claude line of that size has been observed. |
| Lenient forms remain where captures do not cover a transform. | C1-5. | Two candidates ack none (mvp §2.3). |

## 6. PR split

1. **C1a: read surface.** D1, D2 and the canonical fixes named for C1a. C1-11, C1-12. Runs beside C1b.
2. **C1b: hooks.** D3–D9, D11; settings injection first, then the fixture capture, then `ClaudeDecoder`, the per-agent dispatch, `panic::recoverable` around `parse`, card resolution and stale cards, the version probe, and C1b's canonical fixes. Verifies C1-1 to C1-7, C1-13, C1-14, C1-4's hook half, and C1-10's rebind half on its own.
3. **C1c1: large blobs.** D14's store side: migration V4, parts on write, read, and `/api/blobs`, event-store §2.4–§2.5. Independent of C1a and C1b.
4. **C1c2: transcript tailer.** D10, D13; `open_regular`, the tailer, continuity, transcript fixtures, `panic::recoverable` per line. After C1c1. Its FakeCli and store tests need nothing from C1b (`session_bound` already stores the path); real transcript captures need C1b's binding. Verifies C1-8, C1-9, C1-10's tailer half, C1-4's line half.

M1 dogfooding runs after all of them, P-18 end to end: kill the daemon mid-turn, `resume` refused with `death_unconfirmed`, `stop --assume-dead` evidence, `--assume-dead --launch`, then the same conversation and history resumed.
