# Chaldea Architecture

## 1. Purpose Layer (Acceptance Criteria)

- **Native CLI fidelity**: When a user or orchestrator launches Claude Code or Codex CLI through Chaldea, the CLI runs inside an interactive PTY and retains all native interactive features (hooks, skills, resume, permissions).
- **Multi-agent orchestration support**: An orchestrator session can spawn isolated child threads (with git worktrees), exchange messages via pull-based `mailbox`, inspect child outcomes, and keep worktree ownership metadata without losing uncommitted or unpublished work.
- **Cross-platform hosts + Android remote**: macOS and native Windows machines act as independent hosts (local SQLite as source of truth); Android connects remotely via a single PWA (Phase 2: Cloudflare Workers + Durable Objects + Cloudflare Access) for reading, approvals, short prompts, and emergency VT keypad recovery.
- **Japanese IME reliability**: Composing and confirming Japanese text on macOS, Windows, and Android never triggers accidental submission, and multi-byte UTF-8 prompts arrive at the target CLI in the adapter's documented expected form, through its input encoding (PTY Bracketed Paste when DECSET 2004 is on, or keyed input for Codex on Windows).
- **Self-healing boundaries**: Unparseable CLI transcripts/hooks are preserved as `raw_unknown` (never silently dropped); stalled startup/non-hook prompts surface a live `alacritty_terminal` VT snapshot and keypad; a dedicated Rescue Agent can inspect sessions cross-cuttingly and emit scoped A2UI recovery panels.

## 2. Decision Classification

### Irreversible Core (Fix Early)
1. **Event & sync contract**: `stream_id`, monotonic `seq`, `schema_version`, `command_id` idempotency, 3-axis thread state (`process` / `turn` / `task`), worktree ownership (`base_commit`, owner, short base path support).
2. **Auth & permission boundaries**: localhost Bearer token + `Host` check, regular vs Rescue scope tokens, browser CF Access vs host Service Token separation.
3. **Crash-only & Windows-compatible foundation**: persisted `session_id` + `--resume`, `PtyRuntime` trait isolation, Job Object / pgid process-tree cleanup, Rust single-binary hook emitter (`chaldea hook-emit`).
4. **PWA origin & Japanese IME foundation**: single-origin strategy (avoiding Private Network Access conflicts) and plain `<textarea>` IME-safe input.

### Reversible Layers (Defer Intentionally)
- Desktop native shell (PWA -> Tauri v2) and Android native wrapper/app (PWA -> Capacitor / Expo).
- Specific UI features and layout details (diff view, desktop split-pane layout, visual styling — wireframes live in `docs/design/chaldea.pen`).
- Phase 2 Cloudflare Workers + Durable Objects relay (added outside local-first MVP).
- Splitting PTY ownership into a separate long-lived process behind `PtyRuntime`.
- Expanding the A2UI component catalog beyond the initial minimal set (5–6 components).

### Unavoidable Landmines (Self-Healing Seams)
- **External CLI schema drift**: Persist `raw_unknown` + CLI version -> add to `fixtures/` contract corpus -> update adapter & verify.
- **Unexpected TUI prompts (trust, login, update, sandbox network)**: `SessionStart` timeout / `unconfirmed` input triggers `NeedsAttention` + `vt_snapshot` -> emergency VT keypad or Rescue Agent A2UI.
- **OS runtime quirks (ConPTY, worktree locks)**: Built-in `chaldea doctor` round-trip self-check.

## 3. Technology Stack

- **Host Core & Daemon (macOS / Windows)**: Rust workspace with Sans-IO separation (`crates/core`, `crates/pty-runtime`, `crates/daemon`) — `tokio`, `axum`, `rusqlite`, an own macOS PTY backend (rustix + `Command`/`pre_exec`), an own `windows-sys` ConPTY backend (Windows), `alacritty_terminal`.
- **Contracts**: Rust types as source of truth -> generated TypeScript types (`ts-rs`) + runtime boundary validation (`packages/contracts`).
- **Client UI (Desktop / Android)**: React + TypeScript (strict) + Vite + Tailwind as a single PWA (`packages/web`).
- **Remote Relay (Phase 2)**: Cloudflare Workers + SQLite-backed Durable Objects (Hibernatable WebSockets) + Cloudflare Access (`packages/relay`).

## 4. The 5 Seams

1. **Sync Seam**: `GET /api/events` replays a stream from `after_seq` or falls back to a projection snapshot when the cursor is invalid, the database `epoch` differs, or the replay exceeds size bounds; `before_seq` pages older history backward. Clients check `epoch` on every response and restart from a snapshot when it changes. WebSocket notifications are notify-then-pull over single-use tickets with an `Origin` check, backed by periodic head broadcasts so missed notifications recover. `command_id` idempotency uses durable receipts (`in_progress`, completed — replayed to the same token only — or `unknown_after_crash`, never re-executed). Offline clients lock input read-only with a freshness indicator (details in `docs/mvp-design.md` §2.4–§2.5).
2. **Ingest & Event Store Seam**: SQLite append-only log in two stream kinds, `host` and `thread:<id>`, each with a gapless `seq`. Events cover thread and launch lifecycle, session binding, transcript generations, readiness and human writes, messages and tool activity, state and approvals, inputs, mailbox, tasks, surfaces, VT snapshots, worktrees, and `raw_unknown`; `artifact_diff` waits for the diff view (full catalog in `docs/mvp-design.md` §2.1). The envelope is open: readers decode payloads by `kind` and keep an unknown kind, newer `schema_version`, or invalid payload as a generic event, never failing the stream. Thread state is the three axes plus an attention set of causes, each cleared by its own event. Explicit `session_id` / `transcript_path` only (no implicit directory guessing); generation + `(path, offset)` committed atomically with events; `transcript_path: null` allowed (Codex); large tool outputs are offloaded by reference with a preview.
3. **Agent Control & Adapter Seam**: `chaldea spawn / send / wait / stop / mailbox`; input state machine `queued -> sending -> sent -> acked / unconfirmed`, with `rejected` and `cancelled` (zero bytes written) and `dismissed` as the other terminal states, never auto-resending `unconfirmed`. A queued input is written only with positive readiness evidence newer than the last write of any origin. An ack is a `UserPromptSubmit` of the same launch, after the input's stream position, equal to its expected form, with no write of another origin in between; anything ambiguous leaves the input `unconfirmed`. Adapter capability table keyed by `(agent, os)`; worktree short base path override (e.g., `C:\wt\...` for Windows MSVC `link.exe` 260-char limit) (details in `docs/mvp-design.md` §2.3, §2.6–§2.7).
4. **Extension & Rescue Seam**: One-shot JSON hooks (`before_spawn`, `after_close`, `attention`) + authenticated `POST /events`; Rescue Agent token with cross-session read (`events`, `raw_unknown`, `vt_snapshot`, `doctor`) and scoped A2UI (`Host | Workspace | Thread`) + `surface_action` execution (details in `docs/mvp-design.md` §2.8).
5. **PTY Seam**: `PtyRuntime` trait sealing spawn and POSIX PTY / Windows ConPTY differences, with one shared `Session` built on it for every backend (single-writer submission with origin tracking, snapshots, output subscription for attach, resize, tree kill, bounded close), `alacritty_terminal` headless VT query responder (DSR, DA1, OSC 10/11, kitty keyboard, wide-char), Job Object / pgid termination, and crash-only `--resume` (details in `docs/design/pty-runtime.md`, `docs/design/pty-unix.md`, `docs/design/pty-windows.md`).

## 5. External Quirks (Observed Facts)

Observed on macOS with Claude Code 2.1.322 and Codex CLI 0.170.0, and on one native Windows host (inbox ConPTY, console code page 932, build 10.0.26200) with Claude Code 2.1.326 and Codex CLI 0.169.0 / 0.171.0 where marked (spike evidence: `docs/spikes/pty-hooks-spike.md` §3).

- **Claude Code**:
  - New folder trust prompt defaults to `No, exit` — never blindly send `Enter`.
  - Launch-time `--settings <temp.json>` + `--session-id <uuid>` cleanly injects hooks without touching global settings, and `SessionStart` arrives at startup carrying the given session id.
  - `UserPromptSubmit.prompt` is Claude's own rendering of the input, not the pasted bytes: TAB becomes 4 spaces, combining sequences are NFC-composed, and large pastes arrive wrapped in `<pasted_content id="…">`.
  - MCP servers from `--mcp-config` run as descendants of the CLI process; they need `"type": "stdio"` and their env stated explicitly.
- **Codex CLI**:
  - Startup can present prompts before the first turn (Update available, Folder trust, `Hooks need review`).
  - No hook fires at startup: `SessionStart`, `UserPromptSubmit` and `Stop` all fire when the first turn runs. Readiness therefore cannot be gated on `SessionStart`. The adapter passes the first prompt as the positional argument and never writes to the PTY before the session is bound. Inside the review dialog, digit keys pick options (`2` = "Trust all and continue"), so stray input there can approve hooks.
  - Hooks passed via `-c hooks.<Event>=[…]` (source `<session-flags>`) are trusted once and persisted in `config.toml` under `/<session-flags>/config.toml:<event>:<group>:<index>`. The key does not depend on cwd, so the same trust covers every worktree. Changing the command string retriggers `Hooks need review`, so hook command strings must stay fixed while per-session URL/token/thread ID pass via environment variables, which reach the hook process. Trust may need renewal after a Codex upgrade.
  - Without `--no-daemon`, the CLI attaches to a shared, long-lived `codex app-server` daemon, whose version can differ from the CLI's. Session MCP servers then run as children of that daemon, outside the PTY process tree, and survive `stop`. The adapter must launch Codex with `--no-daemon`.
  - `transcript_path` can be `null`.
- **`portable-pty`** (not used by either backend): rejected as an alternative. `0.9.0` enables `PSEUDOCONSOLE_INHERIT_CURSOR` on Windows ConPTY (stalling input until `ESC[6n]` is answered); `0.8.1` fixes ConPTY flags at `RESIZE_QUIRK | WIN32_INPUT_MODE`, loads a bare `conpty.dll` through the DLL search path, inverts `kill`'s result, and offers no job list or suspended start (allowing assign-after race escapees). On Unix, its spawn path closes std's exec-error pipe in `pre_exec`, falls back to `$HOME` for a missing cwd, injects `SHELL`, writes `\n` + VEOF on writer drop, and leaves a CLOEXEC window in `openpty` (`docs/prior-art.md` row 1d; `docs/design/pty-unix.md` §3; `docs/design/pty-windows.md` §3).
- **Windows PTY backend and process tree**: an own `windows-sys` backend calls `CreatePseudoConsole` with flags `0` (inbox `kernel32.dll` only, never a `conpty.dll` from the search path) and `CreateProcessW` with `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE` and `PROC_THREAD_ATTRIBUTE_JOB_LIST`, placing the child in a kill-on-close job from creation without breakaway (`BREAKAWAY_OK` and `SILENT_BREAKAWAY_OK` unset), with `CREATE_SUSPENDED` + assign + resume as fallback when the job list is rejected. Output reaches EOF when conhost, the output pipe's last writer, closes its end, normally at `ClosePseudoConsole` on teardown (`docs/design/pty-windows.md`). Codex runs hook commands in a kill-on-close job of its own when it can, launches them uncontained when it cannot, and keeps successful hooks' descendants (`hooks/src/engine/command_runner.rs:286-346`, `utils/pty/src/win/job.rs:205`); stop therefore keeps the recorded-descendant kill alongside the job.
- **Windows inbox conhost (ConPTY)**: answers DSR 5/6 and DA1/DA2 itself, swallows OSC 10/11 queries, and forwards the kitty keyboard query to the host. A reply conhost writes can land inside a bracketed paste body. It loses an escape sequence split across two host writes, so every sequence goes out in one write. It buffered a 64 KiB paste to a child that stopped reading without blocking the writer.
- **Claude Code on Windows** (2.1.326): bracketed paste over ConPTY delivers Japanese, astral, and multi-line prompts byte-equal, and combining sequences equal after Claude's own NFC composition.
- **Codex CLI on Windows** (0.169.0, 0.171.0): it clears `ENABLE_VIRTUAL_TERMINAL_INPUT` and reads Win32 key records, so bracketed paste never arrives as a paste (CR newlines submit each line, LF newlines are dropped). The adapter capability table selects keyed input (`win_keys`, `docs/mvp-design.md` §2.7) for it, not `?2004h`:
  - Launch with `-c tui.disable_paste_burst=true`. With paste-burst detection on, fast key input can turn the submitting Return into a newline (`tui/src/bottom_pane/chat_composer/reconnect.rs`); turning it off eliminated the missed submits in controlled runs (`docs/spikes/pty-hooks-spike.md` §3).
  - Text encoding: at the console boundary (`ReadConsoleInputW`), inbox conhost delivered U+200D, U+FE0F, U+2764, U+3099, and U+309A written as UTF-8 only on an Alt-key release, and each as a key-down when written as a win32-input-mode key record; Codex's crossterm fork turns such a release into a key release, which the composer ignores, while rebuilding astral characters from surrogate units (`parse.rs:46`, `:200`). The planned `win_keys` encoding therefore sends non-ASCII BMP scalars as win32-input-mode key records and astral scalars as UTF-8 (`docs/mvp-design.md` §2.7). Sending records for every non-ASCII BMP scalar has not yet run end to end in Codex; that is the encoding's first MVP test.
  - Newline and submit: a win32-input-mode Shift+Enter record (`ESC[13;2u` written by the host loses the newline). Send only to a ready composer (after the previous turn's `Stop`), followed by one Return after a delay (300 ms in tests); a missing `UserPromptSubmit` leaves the input `unconfirmed`, never a second Return (an extra Return can accept a popup, run a slash command, or act on a queued draft). Every escape sequence goes out in one write.
  - Leading and trailing whitespace is trimmed by Codex, and with paste-burst detection off a TAB submits early, so both are rejected unless explicitly allowed. Composer triggers apply to typed input: a leading `/`, `!`, or `?` and an `@` token at the cursor change how input is handled, and Tab queues the message. Without `--no-daemon`, Codex on Windows ran `node.exe` / `node_repl.exe` inside the launched tree, with no separate warm server observed.
  - Outside-job PowerShell: a packaged PowerShell (`Microsoft.PowerShell_7.7.0.0_x64__8wekyb3d8bbwe`, image under `WindowsApps`) whose reported parent was `codex.exe` ran in another job outside Chaldea's (no captured hook ancestry matched it), and it and its `conhost.exe` were dead after job termination before any pid fallback. How it came to be outside the job (e.g. packaged-app activation) is unverified (`docs/spikes/pty-hooks-spike.md` §3).
- **Windows MSVC**: `link.exe` fails (`LNK1104`) on paths exceeding 260 characters; worktree base path must be configurable per workspace.
- **Open items for the MVP**:
  - **Codex on Windows keyed input**: end-to-end verification of the `win_keys` encoding (see **Codex CLI on Windows** above and `docs/mvp-design.md` §2.7).
  - **Human pastes through `chaldea attach` to Codex on Windows**: with `tui.disable_paste_burst=true`, human pastes through the outer terminal also arrive as key records without burst capture, so plain Enter or Tab can submit or queue early; the attach path is planned to apply the same keyed-input encoding (including Shift+Enter records for newlines), which needs end-to-end verification.
  - **Codex hook trust renewal after upgrades**: hook trust hashes can flip to `Modified` after a Codex upgrade (`openai/codex#58011`), so the adapter should record the CLI version alongside hook trust state and treat a post-upgrade `Hooks need review` prompt as an expected startup stall.
  - **Windows hook receiver**: on Windows, 20 of 22 spike B-8 checks passed; two cases remain open with unestablished causes (`docs/spikes/pty-hooks-spike.md` §3): `deadline_slow_head` (receiver wrote 408, client observed no status) and `non_numeric_content_length` (`Content-Length: +5`, body withheld: receiver wrote 408 instead of rejecting with 411, client read 400). Daemon hyper/middleware expectations are in `docs/mvp-design.md` §2.5.
  - **Daemon parent job check**: verify at startup that the daemon is not inside a `KILL_ON_JOB_CLOSE` job inherited from the launching terminal, which would take down the daemon and its sessions when that terminal closes (`docs/prior-art.md` row 8).
  - **Windows build coverage**: all Windows runs were on one host (only build `10.0.26200` has been recorded); verify ConPTY and hook behavior on additional Windows builds.

## 6. Verification Strategy

- **Real CLI contract tests (`fixtures/`)**: Versioned real transcripts and hook payloads (highest priority against upstream CLI drift).
- **PBT (`proptest` / `fast-check`)**: 3-axis state machine, input ack transitions, client reducer.
- **Targeted model checking (`stateright`)**: Scoped strictly to startup crash, offline event buffering, and retry after lost response on the Sync Seam.
- **Fuzzing (`cargo-fuzz`)**: JSONL line parser, hook payload decoder, VT escape responder.
- **Cross-OS CI + E2E**: macOS + Windows CI matrix (`core` + `FakePty`), `chaldea doctor`, Playwright E2E (desktop + mobile viewports, including IME composition guard tests).
