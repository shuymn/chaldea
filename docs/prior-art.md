# Prior Art: PTY, Hooks, Paste, VT, Process Trees

Rule served: write our own code only where trusted existing implementations (libraries, OSS solving the same problem, standards) cannot do the job. Each mechanism below lists the widely used approaches, then the decision for Chaldea and why. Where Chaldea picks the less common approach, the reason says so.

Surveyed 2026-11-21 by reading source (shallow clones, default branch at that date) and primary docs. Evidence paths are relative to each repository root. Anything not read in source or docs is marked **unverified**.

## Mechanism Comparison

| Mechanism | Options found (with evidence) | Decision for Chaldea | Reason |
|---|---|---|---|
| **1a. Windows tree kill: what kills the tree** | (1) **Job Object `KILL_ON_JOB_CLOSE`**: Zed `crates/util/src/process.rs:55-127` (non-PTY children such as agent servers and MCP), herdr `src/platform/windows.rs:1310-1440` (status commands only), process-wrap `src/windows.rs:210-275`. (2) **Console process list**: node-pty forks a helper that calls `AttachConsole` + `GetConsoleProcessList`, then `process.kill`s each pid (`src/windowsPtyAgent.ts:206-251`, `src/conpty_console_list_agent.ts`); only when not using the bundled conpty.dll. T3 Code relies on this for terminals (`apps/server/src/terminal/Manager.ts:2172-2173`). (3) **`taskkill /T /F`**: T3 Code for piped (non-PTY) children (`apps/server/src/process/SpawnWorker.ts:487-512`). (4) **Toolhelp ppid walk + `TerminateProcess`**: herdr PTY panes (`src/platform/windows.rs:2770-2805`). It opens each pid with only `PROCESS_QUERY_LIMITED_INFORMATION` before `TerminateProcess`, which lacks `PROCESS_TERMINATE` and probably fails (unverified at runtime). (5) **Nothing beyond `ClosePseudoConsole`**: Windows Terminal (`ConptyConnection.cpp`; a code search for `JobObject` in microsoft/terminal hits only tests and tools), WezTerm `pty/src/win` (no job), Alacritty `tty/windows` (no job). | **Adopt** a Job Object as the primary mechanism, with a recorded-pid fallback (`docs/design/pty-windows.md` §2.5). | Of the surveyed tools, only Job Objects make descendants die with a handle and catch processes that detach from the console. A console list misses children that use `DETACHED_PROCESS`/`CREATE_NO_WINDOW`, for example the MCP servers Claude and Codex start. A ppid walk races pid reuse. Terminals rely on conhost closing its clients and accept leaks. Nested jobs work since Windows 8, so the "already in a non-nestable job" limit applies only if the parent job sets UI limits ([Nested Jobs](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs)). |
| **1b. Windows: closing the assign-after-spawn race** | (1) **Assign after spawn and accept the race**: Zed documents it explicitly (`crates/util/src/process.rs:76-88`: "descendants ... spawned between `spawn()` ... and the assignment ... escape the job. Closing it fully would require `CREATE_SUSPENDED`"). (2) **`CREATE_SUSPENDED` → assign → resume**: process-wrap always does this (`src/windows.rs:64-67`, `lib.rs:122`); herdr does it for status commands (`src/platform/windows.rs:1314`, `:1363`, `:1378-1420`). Both resume by walking Toolhelp threads because std's `Child` hides the thread handle. (3) **`PROC_THREAD_ATTRIBUTE_JOB_LIST`**: assigns jobs atomically at `CreateProcess`, Windows 10 / Server 2016+ ([UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute)). Codex CLI 0.171.0 uses it together with `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE` for its own PTYs (`codex-rs/utils/pty/src/win/procthreadattr.rs:32-33,84-95`, `psuedocon.rs:179`, flags `PSEUDOCONSOLE_RESIZE_QUIRK` only at `:144`, `kernel32.dll` named explicitly at `:94`, `ReleasePseudoConsole` when available); none of the other surveyed tools use it. (4) **Job-first launcher shim**: no surveyed tool does this. portable-pty 0.8.1 builds an attribute list sized for one attribute (`src/win/psuedocon.rs:124-125`, `procthreadattr.rs`) and keeps `pi.hThread` as `_main_thread` (`psuedocon.rs:165`), with no way to add flags or attributes. `conpty 0.7.0` (`src/process.rs:315`), `winpty-rs 1.0.8` (`src/pty/conpty/pty_impl.rs:600`), Alacritty (`tty/windows/conpty.rs:207`), WezTerm `pty` main, and herdr's patched 0.9.0 (`vendor/portable-pty/src/win/psuedocon.rs:362-368`) are the same: none expose suspended creation or a job list. | **Adopt `PROC_THREAD_ATTRIBUTE_JOB_LIST`** (with `CREATE_SUSPENDED` + `ResumeThread(pi.hThread)` only if JOB_LIST fails), not a launcher shim. It lives in Chaldea's own `windows-sys` ConPTY backend (row 1d). | JOB_LIST is the documented OS mechanism for this exact race. As a portable-pty patch it is about 25 lines: attribute-list capacity 2 plus one `UpdateProcThreadAttribute`. herdr shows the maintenance pattern: four documented patches over vendored portable-pty with removal conditions (`vendor/portable-pty.patches.md`). A shim adds a process layer that every tree walk and `wait` has to see through. Codex CLI 0.171.0 combines JOB_LIST with `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE` in production (above); the spike's Windows run did too (report `5feaeaeb`, C-3 `job_first`: branch `job_list`, zero escapees, FakeCli `spawn-tree` only, inbox conhost), while its forced assign-after run had race escapees (`held/race_free`). In the spike's later Windows runs (`d97ee701`, `06f1a5d8`, `5bda54b0`) every raw launch of real Claude Code and Codex sessions took the `job_list` branch with flags 0 and 0x6, with no hung close. On `windows-latest`, `crates/testkit/tests/pty_windows.rs` checks both branches with FakeCli (`child_is_in_the_job_from_creation`, `forced_fallback_takes_the_suspended_branch`); real CLIs on Windows wait for mvp PR 15 and PR 23. |
| **1c. Job Object wrapper crate** | `process-wrap 10.0.1` (watchexec; 28.5M downloads): `JobObject` wraps only `std`/`tokio` `Command`, and its helpers are `pub(crate)` (`src/windows.rs:210`, `:278`), so it cannot wrap a custom `CreateProcessW` child. `command-group 5.0.1`: the same Command-only model, last release 2023-11. `win32job 2.1.0`: `Job::assign_process(handle)` takes any raw handle (`src/job.rs:89`), so it works with `child.as_raw_handle()`, but it pulls in the `windows` crate. Zed (`crates/util/src/process.rs:150-230`) and herdr hand-write about 60 lines of `windows-sys` calls. | **Reject** process-wrap and command-group for PTY children; **adopt** them for Chaldea's own non-PTY spawns in the daemon (`--version` probes, git). **Build ourselves**: `windows-sys` calls for the PTY job, as in Zed and herdr; `win32job` is an acceptable alternative. | The Command-wrapping crates cannot wrap a child started through `CreateProcessW` with a pseudoconsole attribute list. For non-PTY spawns, process-wrap already solves the race with `CREATE_SUSPENDED`, and the daemon should not repeat that work. |
| **1d. ConPTY backend crate** | portable-pty 0.8.1. portable-pty 0.9.0 / WezTerm `pty` main: adds `PSEUDOCONSOLE_INHERIT_CURSOR` (`pty/src/win/pseudocon.rs:85-87`). herdr runs 0.9.0 with it and answers DSR through libghostty. `conpty 0.7.0` (last release 2024-09; no job, no flags API). `winpty-rs 1.0.8` (adds the winpty fallback; no job). Alacritty `tty` (flags `0`, `tty/windows/conpty.rs:123-129`; Zed uses it through an Alacritty fork, `Cargo.toml:544`). | macOS uses an own backend (rustix PTY + `Command`/`pre_exec`, `docs/design/pty-unix.md` §3); portable-pty is not used. **On Windows, build an own `windows-sys` backend** (`docs/design/pty-windows.md` §3): `CreatePseudoConsole` with flags 0 + `CreateProcessW` with JOB_LIST (`CREATE_SUSPENDED` fallback), loading ConPTY from `kernel32.dll` only. Rejected: unchanged portable-pty (assign-after race, bare `conpty.dll`, inverted `kill`) and a vendored patch (it would need most of these fixed plus herdr's patches, keeping `winapi`-era dependencies). Flags 0x2 (Codex's choice; untested for Chaldea) is the candidate if a resize problem appears; it is a one-constant change. | No surveyed crate removes the job race or adds anything Chaldea needs. herdr's four patches show where portable-pty breaks on real Windows hosts: DLL search, raw `cmd` tails, malformed registry environment blocks, and directories on PATH (`vendor/portable-pty.patches.md`; patches 0003 and 0004 also apply to 0.8.1's `cmdbuilder.rs` PATHEXT walk). portable-pty 0.8.1 fixes ConPTY flags at `PSEUDOCONSOLE_RESIZE_QUIRK \| PSEUDOCONSOLE_WIN32_INPUT_MODE` (`src/win/psuedocon.rs:86`), loads a bare `conpty.dll` through the search path (`:54`), inverts `WinChildKiller::kill` (`src/win/mod.rs:70-79`), and lacks JOB_LIST or `CREATE_SUSPENDED` (row 1b). On Unix, `close_random_fds()` runs `read_dir` and grows a `Vec` inside `pre_exec` (`src/unix.rs:118-143`, called at `:239`), which is not async-signal-safe, and `UnixMasterWriter::drop` writes `\n` + VEOF to the PTY (`src/unix.rs:351-363`). |
| **1e. Loading a side-loaded `conpty.dll`** | portable-pty 0.8.1 loads a bare `conpty.dll` through the DLL search path (`win/psuedocon.rs:51-58`). herdr calls this a DLL-planting risk and patches it to load only a hash-verified bundled OpenConsole by absolute path, otherwise kernel32 (`vendor/portable-pty.patches.md` §0001; issues herdrdev/herdr#761, #1533; microsoft/terminal#17452). node-pty ships an optional bundled conpty.dll (`useConptyDll`, `src/windowsPtyAgent.ts:71`). | **Adopt herdr's policy**: never resolve `conpty.dll` through the search path; import ConPTY from `kernel32.dll` only (`docs/design/pty-windows.md` §3). | Loading a DLL found on PATH into a daemon that holds Bearer tokens is a code-injection vector. |
| **2. Unix tree kill** | `killpg` on a `setsid` leader: Zed `crates/terminal/src/pty_info.rs:149-170` (SIGTERM, then SIGKILL) and `crates/util/src/process.rs:109-116`; herdr status commands (`src/platform/unix_common.rs:605-610`). Session enumeration: herdr collects every pid whose `getsid()` matches (`src/platform/macos.rs:1126-1140`), then sends HUP → TERM → KILL with 250 ms grace each (`src/pane.rs:1760-1800`). T3 Code sends HUP → TERM → KILL to the shell only, because interactive shells forward SIGHUP to their jobs (`Manager.ts:2166-2230`). process-wrap `ProcessGroup`/`ProcessSession` work only for `Command`. tmux and claude-squad kill the tmux session. | **Adopt** `killpg` (SIGHUP → SIGTERM → SIGKILL) with `getsid` session enumeration and recorded-pid fallback (`docs/design/pty-unix.md` §2.5). | The backend's `pre_exec` calls `setsid`, so pgid = sid = child pid, the same setup as Zed and herdr. herdr's `getsid` scan also catches descendants that called `setpgid` without `setsid`. CLIs that clean up on SIGHUP, as on terminal close, then get their normal shutdown path. |
| **3a. Headless VT emulator** | `alacritty_terminal`: Zed (fork, `Cargo.toml:544`; `crates/terminal/src/alacritty.rs`). `libghostty-vt` (Zig, through FFI): herdr (`crates/ghostty-vt`, `vendor/libghostty-vt.vendor.json`); T3 Code vendors it under `native/libghostty-vt` (usage not checked). `vt100 0.18.1`: parser and screen only, with no DSR/DA replies; queries reach `Callbacks::unhandled_csi` (`src/callbacks.rs:58`), so we would write the responder. `termwiz` / `wezterm-term`: wezterm-term is not on crates.io; **unverified** beyond that. `vte` alone: parser only. | **Adopt `alacritty_terminal =0.26.0`** (`docs/design/pty-runtime.md` §2.5). | It answers DA1, DA2, DSR 5/6 and kitty natively and surfaces OSC 10/11/4 and the text-area size to the embedder (spike §3). Zed ships it. libghostty-vt has wider coverage (XTGETTCAP, color scheme) but needs a Zig toolchain and C FFI. vt100 would mean writing the responder ourselves. |
| **3b. Who answers terminal queries** | The emulator replies and the embedder supplies colors and size: Zed `crates/terminal/src/terminal.rs:1678-1701` (`PtyWrite`, `ColorRequest`, `TextAreaSizeRequest`); herdr `src/pane/terminal.rs:1161` (libghostty `write_pty` callback) plus its own handling of color and legacy C1 replies, which it reorders by byte offset (`:1491-1530`). Windows inbox conhost under ConPTY (spike run `1b584fe6`, B-5 and B-10): answers DSR 5/6 and DA1/DA2 itself in about 0.1 ms, also with our responder off (DA1 `ESC[?61;6;7;21;22;23;24;28;32;42c`); does not pass OSC 10/11 queries to the host and gives no reply; forwards the kitty keyboard query, which the host must answer; and when the app queries mid-paste, its CPR reply is inserted into the app's input inside the pasted body. | **Adopt** single-writer reply ordering (`docs/design/pty-runtime.md` §2.5). On Windows the responder only covers what conhost forwards (kitty; OSC 10/11 never arrive). | This matches both reference embedders. herdr also orders replies against the input stream by offset, which supports single-writer ordering. That ordering cannot reach replies conhost writes itself, so a Windows app can see a query reply inside its own paste. |
| **4a. Bracketed paste framing** | Every surveyed tool brackets **only when the app enabled DECSET 2004**: Zed `terminal.rs:2478-2486`, Alacritty `alacritty/src/event.rs:1376`, herdr `src/pane.rs:3707-3716` and `src/server/terminal_attach.rs:1-10`, tmux `paste-buffer -p` (`cmd-paste-buffer.c:98`, `:125`), xterm.js `src/browser/Clipboard.ts:21-29`. | **Adopt**: write `ESC[200~` only when `TermMode::BRACKETED_PASTE` is set. Otherwise the input gate stays closed and the input stays `queued` with zero bytes written (`docs/mvp-design.md` §2.3; `core::input::GateClosedReason::BracketedPasteOff`). | A CLI that has not enabled 2004 yet, because it is still starting or showing a trust prompt, would get literal `[200~` text. Waiting writes nothing, so nothing needs a resend; `unconfirmed` is kept for an input that may have reached the CLI (`docs/mvp-design.md` §8 D3). |
| **4b. Paste content sanitization** | Strip ESC: Zed (`text.replace('\x1b', "")`). Strip ESC and `^C`: Alacritty (`event.rs:1386`). Replace ESC with U+241B: xterm.js (`Clipboard.ts:27`). Replace NUL/ESC/DEL with spaces: libghostty `ghostty_paste_encode` (herdr `crates/ghostty-vt/src/bindings.rs:5123`, doc comment). `vis(3)`-escape controls: tmux (`cmd-paste-buffer.c:47-56`). No sanitization: herdr's own path (`src/pane.rs:3707-3716`). | **Adopt rejection** of ESC and C0 controls (including `^C` / `0x03`) except TAB, CR, and LF, and, where the CLI is shown to drop or reinterpret them, of DEL (Codex's paste path and its Windows key path, where a raw `0x7F` becomes Backspace) and C1 controls (Codex's paste path) (`docs/design/input-encoders.md` §2.5, D6). | Every surveyed tool strips or replaces, which is right for interactive clipboard pastes. Chaldea pastes programmatic prompts, so silently changing a prompt would break byte-equality. Rejecting is less common, and that is the reason for it. |
| **4c. Newlines inside a bracketed paste** | LF → CR: xterm.js (`Clipboard.ts:13-15`, before bracketing) and tmux (`cmd-paste-buffer.c:88-94`; default separator `\r`, `-r` keeps LF). LF kept inside brackets: Alacritty (`event.rs:1386-1389`; LF → CR only when unbracketed), Zed (`terminal.rs:2479-2482`), libghostty ("replacing newlines with carriage returns if bracketed is false", `bindings.rs:5123`). LF → CRLF on Windows: herdr (`src/platform/windows.rs:718-720`). | **Adopt `cr`**: LF, CRLF, and a lone CR each become one CR inside the brackets (`docs/design/input-encoders.md` §2.6). | Precedent is split evenly, and herdr changes the form on Windows only, so the spike measured it (`--paste-newline cr\|lf\|crlf`): Claude Code arrived exact in all three modes on macOS (A-6, 2.1.322) and on Windows (C-1, 2.1.326, 30 cases), recording LF; Codex's paste path maps CR and CRLF to LF (`paste_input.rs:210-211`, tag `rust-v0.169.0`; not run on macOS), so its prompt does not depend on the mode. Codex on Windows takes no bracketed paste (row 4d). `cr` is also what Enter sends. |
| **4d. ConPTY input mode / UTF-8 paste** | portable-pty 0.8.1 passes `PSEUDOCONSOLE_WIN32_INPUT_MODE` (0x4) and `RESIZE_QUIRK` (0x2). Current OpenConsole defines only 0x1 (`INHERIT_CURSOR`), 0x08/0x10/0x18 (glyph width), and 0x20 (`AMBIGUOUS_IS_WIDE`) (`src/winconpty/winconpty.h:51-63`, `winconpty.cpp:169-196`), so open-source ConPTY ignores 0x4. win32-input-mode is negotiated in-band with `CSI ?9001h`. Windows Terminal passes 0 by default (`ConptyConnection.cpp:262-295`); Alacritty passes 0; node-pty passes only the optional `INHERIT_CURSOR` (`src/win/conpty.cc:293`). What the **inbox** kernel32 conhost does with 0x4 is **unverified**. GitHub issue searches for ConPTY UTF-8/bracketed-paste corruption returned nothing relevant (**no evidence found**, not evidence of absence). Spike Windows run (inbox conhost via kernel32, flags 0x6, CP 932; reports `5feaeaeb`, `59bc61b8`): Claude Code 2.1.326 passed every bracketed paste case (30 cases, Japanese, astral, decomposed, multiline, chunk 0 and 7; byte-equal except the decomposed entries, equal after Claude's own NFC composition); conhost requested `?9001h`; an escape sequence split across two writes lost its leading bytes (`ESC[201~` → `1~` or `~`), while every whole-write paste passed. Codex 0.169.0 clears `ENABLE_VIRTUAL_TERMINAL_INPUT` on every poll (`codex-rs/tui/src/tui/event_stream.rs:147-161`, `tui/windows_console.rs:9-11`, tag `rust-v0.169.0`), so it reads Win32 key records through a crossterm fork and never sees bracketed paste; it detects pastes by timing (`bottom_pane/paste_burst.rs:160-171`) and reassembles `ESC[13;2u` typed as keys into Shift+Enter (`tui/windows_key_sequence.rs`). Observed: CR or CRLF newlines submitted each line as its own prompt, LF newlines were dropped (conhost maps LF to Ctrl+Enter, which Codex ignores), and combining marks were lost (`が` → `か`, `é` → `e`) where the composer does not filter them. | **Use bracketed paste** for apps that read VT input, and **record which ConPTY is active** (inbox vs. sideloaded) next to `?9001h`. Never answer `?9001h` by switching a bracketed paste to win32-input encoding. **For Codex on Windows, use a per-adapter input encoding** (`docs/architecture.md` §5, `docs/mvp-design.md` §2.7: paste-burst detection off, non-ASCII BMP scalars and the Shift+Enter newline as win32-input-mode records, one Return, trimmable whitespace and TAB rejected; full end-to-end verification is the first MVP test: PR 5 tests the encoder's bytes, PR 15 runs it with real Codex on Windows; Claude's bracketed paste on Windows is mvp P-6, PR 23). Keep every escape sequence inside one write. | With a sideloaded OpenConsole flag 0x4 is a no-op, so any paste difference comes from the inbox conhost version. Bracketed paste over ConPTY is sound for VT-input apps; Codex's own Windows input mode, not ConPTY, is what breaks multi-line and combining input (inbox conhost delivers some UTF-8 characters only on an Alt-key release, and Codex's input stack discards that release). |
| **4e. Delay before Enter after paste** | herdr: 300 ms (`src/app/api/agents.rs:13`, `queue_user_input_submission`). T3 Code and claude-squad: not applicable (SDK / tmux send-keys). | **Adopt** a default of at least 300 ms for real CLIs; keep the sweep (0/100/500). | herdr's 300 ms is the only production value found for driving agent TUIs through a PTY. 100 ms may be too short for Ink-based input. |
| **5a. Hook receiver (HTTP server)** | `tiny_http 0.12.0`: deps `ascii`, `chunked_transfer`, `httpdate`, `log`; last release 2022-10 (79M downloads); reads header lines without a length bound (`src/client.rs:80-100`) and never sets a socket read timeout. `httparse 1.10.1` (hyper's parser): bounded, caller-supplied header array, no I/O. `axum` + `tokio`: the daemon stack (`docs/mvp-design.md` §2.5). Hand-written HTTP/1.1 parsing on `std::net`. herdr uses JSON-RPC over a Unix socket / named pipe (`interprocess`, `src/ipc.rs:10-11`); T3 Code uses in-process SDK callbacks. | **Adopt `httparse`** on a std listener for the spike receiver (and `axum`/`hyper` in the daemon); **reject `tiny_http`**. Request-line and header parsing is better handled by a widely used parser; `tiny_http` cannot bound headers or set a request deadline, while `httparse` leaves I/O and deadlines to the caller. The auth logic stays ours. |
| **5b. Hook emitter (HTTP client)** | `minreq 3.0.0`: **zero mandatory dependencies** (TLS and proxy are opt-in features); `connect_timeout` is derived from the request timeout (`src/connection.rs:205`); about 2.3k lines. `ureq 3.5.2`: TLS stack by default, much larger; whether it reads proxy env by default is **unverified**. T3 Code: no emitter. | **Adopt `minreq`** (default features off), or keep the hand-written POST if the 1 s connect / 3 s total split must be exact. | minreq adds no transitive crates, so the supply-chain cost is one crate. | **6a. Claude Code hook injection** | herdr: installs a command hook **globally** in `~/.claude/settings.json` (`src/integration/claude_settings.rs:65`), and the script exits unless `HERDR_ENV`/`HERDR_SOCKET_PATH`/`HERDR_PANE_ID` are set (`assets/claude/herdr-agent-state.sh:20-23`); it reports `SessionStart` only and derives other state from the screen.
